## 🎯 Goal

Desktop app (Mac + Windows) to run a full Seventh-day Adventist weekly service from one control panel.
The operator sits at the back of the hall, prepares the program the same morning, and during the
service projects hymns, Bible verses, presentations (PDF/PPTX), videos, a break countdown timer,
background music, a bell, and an offering QR — all onto a **second screen** (iPad via Sidecar now;
in church will be a normal TV monitor).

"Done" = the operator never has to touch the projected screen; everything (incl. slide advance,
video transport, audio) is controlled from the app, and projection looks professional.

Packaging (PyInstaller .app + Windows .exe) comes **last**, after all features are stable.

  1. **Click/drag race condition** (the actual root cause of "resize doesn't even start after I
     click a slot"): clicking a slot row to select it *also* fires `_drag_start` (slot drag-reorder
     is bound to `<ButtonPress-1>` on the same `top`/`body` widget used for the selection click).
     The selection click's handler (`click()` in `_render_slot_row`) synchronously calls
     `_render_sections()`, which **destroys the very widget that just received the mouse press**,
     before the matching `<ButtonRelease-1>` can reach `_drag_end` and unbind things. Result: the
     global `<B1-Motion>`/`<ButtonRelease-1>` bindings on `self` (the root window) stay stuck
     forever, and silently hijack the *next* unrelated drag — including the panel-resize divider,
     which then appears completely unresponsive. **Fix:** deferred `_render_sections()` in `click()`
     via `self.after(1, self._render_sections)` so the press/release cycle completes (and
     `_drag_end` fires) before the widget gets destroyed and rebuilt.
  2. **Stale geometry on resize-end:** `_resize_left_end`/`_resize_right_end` (bound to
     `<ButtonRelease-1>` on the divider, added this session to fix content not reflowing) rebuild

     `self._left_panel.winfo_width()` / `.winfo_width()` can still report the **old** width — Tk's
     geometry manager hadn't caught up to the just-configured size yet. Confirmed via temporary debug
     print: `winfo_width()=235` while `self._right_w=406`. The freshly-rebuilt `CTkScrollableFrame`
     bakes in the stale (smaller) width, leaving an empty band. **Fix:** added `self.update_idletasks()`
     immediately before the rebuild call in both `_resize_left_end`/`_resize_right_end`.
  3. **Cold-start stale width:** at app launch, `_build_program_list()`/`_build_right_panel()` run

     real container width" problem hits on the very first render, not just on live resize. **Fix:**

     calling a new `_refresh_panels_after_startup()` method that rebuilds both panels once the window
     has actually had a chance to realize its true geometry.

## ❌ Failed Attempts / Hard-won Knowledge

### Diagnosing "panel resize doesn't work" purely from user screenshots — wasted significant effort
- First two rounds of fixes (rebuilding panel content on `<ButtonRelease-1>`) were based on a
  misread screenshot: the "Campanello" card the user pointed at was the **right panel's contextual
  card** (`_build_right_panel`), not the **center panel** (`_render_center`) — completely different
  code paths. Fixed the wrong thing twice before getting a full-window screenshot that made the
  actual layout (left/divider/center/divider/right) unambiguous.
- **Lesson:** for layout/visual bugs, ask for a **full, uncropped window screenshot** from the start,
  not a cropped region — cropped screenshots without window chrome are very easy to misattribute to
  the wrong panel.

### Automating precise pixel clicks on an 8px-wide divider via remote screen control — very unreliable
- Spent a large amount of effort trying to drag the `_DIVIDER_W = 8`px resize divider via computer-use
  screen automation. Coordinates that worked once often failed on the very next identical-looking
  attempt; a `<B1-Motion>`/`<ButtonRelease-1>` handler sometimes silently never fired with literally
  zero error, with no visual feedback to indicate a miss.
- Added a temporary `print(..., flush=True)` debug line directly inside `_resize_left`/`_resize_right`
  and tailed the background process's redirected stdout file — this was the only way to get a
  reliable, fast yes/no on "did the handler even fire" and "what values did it compute". **This
  pattern (temporary debug prints + reading the redirected `.output` file) is far more reliable than
  visual screenshot comparison for diagnosing event-binding issues — reuse it before reaching for
  more screenshots.**
- Real mouse input from the user is NOT subject to this same imprecision (cursor hover feedback,
  native resize cursor icon, etc.) — don't assume a real user will hit the same wall, but also don't
  assume "my computer-use test worked once" means it's reliably fixed for them either.

### `update_idletasks()` is not scoped per-widget
- Briefly considered calling `self._center.update_idletasks()` vs `outer.update_idletasks()` as if
  they'd behave differently — they don't. `update idletasks` operates on the whole Tcl interpreter's
  pending idle-task queue, not on a particular widget subtree. Calling it on any widget in the same
  app has the same effect.

### `outer._frame.columnconfigure(...)` in the existing resize code is dead code
- `_resize_left`/`_resize_right` wrap a call to `outer._frame.columnconfigure(...)` in a bare
  `try/except Exception: pass`. In customtkinter 6.0.0, `CTkFrame` extends `tkinter.Frame` directly —
  there is no `._frame` attribute, so this always raises `AttributeError` and is silently swallowed.
  Harmless (the real fix is `outer.grid_columnconfigure(...)`, which works fine), but worth knowing
  it's inert if touching this code again — no need to "fix" it, just don't assume it's doing anything.

### (Carried over from earlier sessions — still valid, not re-tested this session)
- PowerPoint AppleScript PNG export fails due to `as` keyword collision → switched to Keynote.
  **NOTE: user wants to drop Keynote entirely, see Next Steps #5 — this whole approach may become
  obsolete, and is also a Windows-compatibility gap since it's macOS-only.**
- Keynote PPTX import timing race — poll-based wait + cache cleanup on failure.
- `winfo_width()` returns 1 before window realized on ProjectionWindow — cached size fallback.
  **Same family of bug as this session's "cold-start stale width" issue — `_size()` in
  `ui/projection.py` already has the right defensive pattern (`_cached_size` fallback); the
  left/right panel code didn't, until this session's fix.**
- Video frame flicker — fixed via `itemconfigure` in-place update instead of delete+recreate.
- `text_color="transparent"` crashes CTkButton — use `text=""` to hide instead.
- `CTkFrame.configure(width=nw)` doesn't trigger grid relayout on its own — also needs
  `grid_columnconfigure(col, minsize=nw)` + `update_idletasks()` **called *after* any code that reads
  `winfo_width()`, not just after the configure call** (this session's stale-geometry bug was exactly
  this ordering mistake, just one level deeper — in the *rebuild* triggered by the resize, not the
  resize itself).

## ✅ Working Solutions (keep these)

- **In-app modals** via transparent overlay frame (`_open_modal`) — never use `Toplevel` for editing
  popups.
- **DB cache** in `core/database.py` (filename → mtime in `config/db_cache/`).
- **PPTX cache** in `config/pptx_cache/{md5(abspath+mtime)[:20]}/` — Keynote re-export only on file
  change (likely to be replaced, see Next Steps #5).
- **Audio:** `music` = seekable single stream (pygame.mixer.music); pause music = Sound channel.
- **Bibles as bundled SQLite** + `tools/convert_bib.py` for new languages.
- **Accent-insensitive search** via `core/textutil.normalize`.
- **Projection auto-fit text** (binary-search font size) for verses/free text.
- **`_proj_pill_prefix`** attribute: set before projecting hymn/PDF so slide counter shows correct
  title.
- **`on_slide_change` callback** from ProjectionWindow → `_update_slide_label()` for real-time pill
  update.
- **`_dl_cancel` flag** checked in yt_dlp progress hook to abort downloads cleanly.
- **`_auto_wrap_label(lbl)` helper** (top of `ui/app.py`, near `_fmt_time`): binds a label so its
  `wraplength` tracks its real pixel width, with a loop guard.
- **Grid-based hover show/hide** for contextual controls (`grid()` / `grid_remove()`), NOT `pack()`
  with conditional packing and NOT `place()` overlays.
- **Per-section/per-instance UI-only state in a dict on `self`, keyed by stable id** (e.g.
  `self._sec_open[sec.id]`) — the right pattern any time a widget's visual/interaction state needs
  to survive a `destroy()` + rebuild cycle, but should NOT be persisted to the schedule data model.
  Remember to clean up the dict entry when the underlying object is deleted.
- **Deferring a destructive rebuild by one tick** (`self.after(1, fn)`) when the rebuild is triggered
  from the same event that started an unrelated drag/grab on the widget being destroyed — cheap,
  visually imperceptible, and avoids a whole class of "stuck global Tk binding" bugs.
- **`probe_video_codec()` / `needs_transcode()` / `transcode_to_h264()`** in `core/video.py` — reuse
  this pattern (probe via `ffmpeg -i ... 2>&1` regex on stderr, since the project doesn't bundle a
  separate `ffprobe`) for any future "is this media file actually playable" checks.
- **Temp files for in-place file transformations must live outside the destination folder**
  (`tempfile.mkstemp()`, not `same_dir/name_suffix.ext`) if the user might independently browse that
  folder (e.g. via a native file picker) while the transformation is in flight. Use `shutil.move()`
  (not `os.replace()`) to move across filesystems/volumes safely.
- **Windows console-flash guard for subprocess calls to console-mode exes** (ffmpeg.exe etc.):
  `creationflags = subprocess.CREATE_NO_WINDOW if sys.platform == "win32" else 0`. Safe to reference
  unconditionally in a module-level constant because Python's conditional expression only evaluates
  the chosen branch — `subprocess.CREATE_NO_WINDOW` doesn't exist on macOS/Linux but is never touched
  there. Reuse this exact pattern for any new subprocess call that shells out to a console tool.
- **`winfo_exists()` guard before configuring a widget from a deferred `self.after(...)` callback**
  — `hasattr(self, "_attr")` is NOT enough, since the Python attribute can still point to an already
  `.destroy()`-ed Tk widget. Pattern used this session: a small `safe_cfg(attr_name, **kwargs)`
  closure that does `w = getattr(self, attr_name, None); if w is not None and w.winfo_exists(): w.configure(**kwargs)`.
  Reuse this anywhere a background thread schedules a UI update that might land after the user has
  navigated away from that view.

## ⚠️ Gotchas / Traps

- **Everything must work identically on Windows** — see Dependencies & Setup above. This applies to
  every change, not just video/codec work.
- **Close Python before editing code** — user has 16GB RAM. Always `pkill -f "python.*main"` before
  starting a work session and immediately after testing. **This session repeatedly ended up with
  multiple stray instances during heavy iterative testing — always verify with
  `ps aux | grep main.py` after a `pkill`, don't assume it worked.**
- **macOS case-insensitive FS**: `HANDOFF.md` and `handoff.md` are the same file.
- **Don't reintroduce `Toplevel`** for editing popups — use `_open_modal`.
- **`cursor="hand2"`** was replaced with `"pointinghand"` — don't revert.
- **`text_color="transparent"`** crashes CTkButton — use `text=""` to hide button labels.
- **Don't use `place()` for hover overlays** — caused an opaque white-box rendering bug; use grid
  `grid()`/`grid_remove()` instead.
- **Don't compute wraplength without a "value changed" guard** — causes infinite `<Configure>` loops
  that freeze the whole app.
- **`acts.pack(side="right")` must come BEFORE `lbl.pack()`** in slot rows where `pack()` is still
  used — otherwise `expand=True` on `lbl` takes all space and `acts` gets zero.
- **`on_close` re-entry guard**: `ProjectionWindow.close()` clears `_on_close = None` before calling
  it. Don't remove this.
- **Projection on single monitor** (no Sidecar): falls back to `-fullscreen True` on primary,
  covering the app window. Use `_stop_projection` / "Togli proiezione" to get back.
- **`_dl_cancel`** is an instance attribute initialized in `_view_media()` — use
  `getattr(self, "_dl_cancel", False)` if accessed before that view is visited.
- **Any widget bound on `<ButtonPress-1>`/`<Button-1>` that ALSO triggers a synchronous
  destroy+rebuild in its own click handler is a latent stuck-global-binding bug waiting to happen**
  (see this session's slot click/drag race). If you add a new clickable element that both (a) starts
  some kind of drag/grab via root-level `self.bind(...)`, and (b) also has a plain click handler that
  rebuilds its own parent container, defer the rebuild with `self.after(1, ...)` from the start.
- **`update_idletasks()` ordering matters**: call it *after* changing a widget's configured
  size/grid constraints and *before* any code that reads `winfo_width()`/`winfo_height()` on it or
  its children — not just "somewhere after the resize".
- **Smoke tests** live in the scratchpad (session-specific path), NOT in the repo. Recreate if needed.
- **Reset `config/settings.json`** after smoke tests — tests dirty it. This session specifically
  dirtied `left_panel_width`/`right_panel_width` to 391/404 during divider-drag debugging; reset to
  240/240 at the time, but the user has since saved their own real values (currently 302/412) through
  normal use — that's fine, don't touch it again unless it looks like test pollution.
- **`pkill -f "Python.*main.py"` killed an instance running in the user's own real terminal more than
  once this session** — when a process shows up with tty `s000` (not `??`) in `ps aux`, that's
  probably the user's own interactive terminal, not a Claude-spawned background one. Still safe to
  restart since they need to relaunch after every code change anyway, but worth flagging to the user
  before doing it, rather than assuming silently.
- **No automated tests exist** for `ui/app.py`. Verification method used:
  `python3 -c "import ast; ast.parse(open('ui/app.py').read()); print('OK')"` after every edit, plus
  manual launch + live testing. This session additionally used: (a) temporary `print(..., flush=True)`

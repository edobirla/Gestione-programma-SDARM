## 🎯 Goal

Desktop app (Mac + Windows) to run a full Seventh-day Adventist weekly service from one control panel.
The operator sits at the back of the hall, prepares the program the same morning, and during the
service projects hymns, Bible verses, presentations (PDF/PPTX), videos, a break countdown timer,
background music, prayer requests, a bell, and an offering QR — all onto a **second screen**, without
ever touching the projected screen themselves.

"Done" = the operator never has to touch the projected screen; everything (incl. slide advance, video
transport, audio) is controlled from the app, and projection looks professional.

Packaging (PyInstaller .app + Windows .exe) comes **last, after everything else** — see Next Steps.

A **separate design-improvement phase has now started**, using a different "Claude design"
chat/tool (not this codebase session) with `design-review-brief.md` + `screenshot app/` as its
input. See Next Steps for what's left to prep for that, and Notes for why it's a separate tool.

- **GC / Tcl thread-safety deadlock — the deepest bug this session, found while chasing bug #2 above
  before the real fix was known.** Symptom: downloads would silently hang forever, no exception, no
  timeout. Root cause (confirmed via `sys._current_frames()` stack-trace dump of the stuck thread):
  `tkinter.font.Font.__del__` was being invoked on the **background download thread** during
  `import yt_dlp` (specifically inside the `yt_dlp → cookies → aes → dependencies → mutagen →
  mutagen._util` import chain) — CPython's cyclic garbage collector can fire on any thread, and this
  particular import chain happened to trigger a collection that reaped a `Font` object, which needs to
  call into Tcl but cannot safely do so off the main thread. Result: permanent silent deadlock, not a
  crash. **Fix:** `gc.disable()` at module load in `ui/app.py`, plus `_periodic_gc()` — a manual
  `gc.collect()` on the main thread only, rescheduled every 30s via `self.after(30000, ...)`. This is a
  broad, session-wide mitigation, and likely also explains the *"seemed fixed but stopped working
  again"* pattern the user had previously reported for the video black-screen bug in earlier sessions
  — a flaky GC-timing-dependent failure, not a deterministic one.

## ❌ Failed Attempts / Hard-won Knowledge

### The GC/Tcl deadlock took multiple misleading "successful" isolation tests before reproducing
Isolated attempts that all worked fine, in this order: raw thread + cold `yt_dlp` import; `ui.app`
imported then cold import; full `App()` instantiated then cold import; `_nav("media")` called then
cold import. **All of these succeeded**, which was misleading — the deadlock only reproduced through
the *exact* code path of `_download_youtube()`'s actual closure, triggered by a real download. Only
dumping the stuck thread's live stack trace via `sys._current_frames()` found the real mechanism.
**Lesson: a bug that "won't reproduce in isolation" across several plausible simplifications may still
be real — narrow the reproduction to the *exact* call path before concluding it's not reproducible, and
prefer inspecting a live stuck thread's stack over guessing from code reading alone.**

### Computer-use screenshot capability broke mid-session, recovered later
Screenshot capture returned `nil` (permission missing or `SCContentFilter` failure) and
`request_access` timed out after 300s partway through the session. Fell back to headless Tkinter
verification (real `App()`/`ProjectionWindow` instantiated against a scratch `settings.json`, with
`tkinter.font.Font.__init__` monkey-patched to spy on constructor args) for that stretch. Screenshot
capability recovered later in the session (confirmed working again during video/audio slider testing).
**Lesson: if computer-use breaks mid-task, say so plainly and fall back to headless verification rather
than guessing or claiming visual confirmation you don't have.**

## ✅ Working Solutions (keep these)

- **Box-based autofit text rendering** (`(x, y, w, h)` as 0..1 fractions of screen size, binary-search
  the largest font that fits via `_fit_text`/`_fit_table`) — the pattern for anything projected that
  needs to be user-repositionable/resizable "like a Word text box." Reuse for any future projected
  element that needs this (currently: verse text, verse reference; prayer list uses `_fit_table`
  specifically for its two-column layout).
- **Drag-to-move / drag-to-resize preview pattern** (small corner handle for resize, click-drag body
  for move, distinguished via hit-testing near the handle) — implemented for the Bibbia settings live
  preview (`_render_verse_preview` + `_on_verse_preview_*`). Reuse for any future "live WYSIWYG
  settings preview."
- **`gc.disable()` + manual periodic `gc.collect()` on the main thread only** — the fix for the whole
  class of Tk/Tcl-thread-safety deadlocks that can be triggered by *any* background thread's imports
  or object lifecycles, not just yt-dlp's. If a future session adds another background thread (e.g. for
  a different download/network task), this protection already covers it — no new code needed per
  thread.
- **Persistent flags on `self` guarded by `hasattr()`** (`self._dl_active`, `self._dl_status_text`) —
  the pattern for UI state that must survive a full widget-tree rebuild (e.g. navigating away and
  back). Initialize once, never unconditionally reset in the render function.
- **"Mid-drag guard" at the top of a periodic full-rebuild function** (`_refresh_now_playing`'s check
  of `self._np_video_dragging`/`self._np_audio_dragging`) — the pattern for adding an interactive
  slider/control to a UI element that's otherwise destroyed-and-recreated on a timer. Reuse this
  exact shape for any future periodic-rebuild panel that needs a draggable control.
- **`_proj_registry()`** — still the one place to wire a new projection mode into keyboard nav and
  "Togli proiezione." Prayer requests (single + list) are now registered here alongside verse/inno/
  video/pdf/table modes.
- **Headless testing via scratch-settings `App()` instantiation** (`core.settings.SETTINGS_PATH`
  monkey-patched to a scratch file before `import ui.app`) — safe way to exercise real UI logic without
  touching the user's real config or needing a live display. Used extensively this session for
  download-flow and UI-state-persistence verification.
- Everything from previous handoffs still valid and unchanged: in-app modals via `_open_modal` (never
  `Toplevel`), DB cache in `core/database.py`, bundled-SQLite Bible + `tools/convert_bib.py`,
  accent-insensitive search, `self._proj_mode` string tag, overlay state on `ProjectionWindow`
  (`_overlay`, independent of `_mode`), `on_nav`/`on_quick` callbacks, `_slot_rows`/`_section_wraps`
  tracking dicts, `.pack(after=sibling)` for reordering without unmapping.

## ⚠️ Gotchas / Traps

- **`gc.disable()` at module load in `ui/app.py` is load-bearing** — see Dependencies & Setup. Don't
  remove without understanding why it's there (GC/Tcl thread-safety deadlock, see Failed Attempts).
- **`PlaylistChannel` (pause music) has no seek/position API** — don't build a draggable seek bar for
  it like `AudioPlayerWidget`/`VideoPlayerWidget` have; only play/pause/skip/prev/track-name are
  possible without deeper changes to `core/audio.py`.
- **Remote control from phone/tablet is permanently cancelled** — do not re-propose. The user was
  explicit ("il punto 1 non lo facciamo più").
- **Headless test scripts that instantiate `App()` point at the real settings file by default** —
  always monkey-patch `core.settings.SETTINGS_PATH` to a scratch file *before* `import ui.app` in any
  throwaway verification script, or it will read/write the user's real `config/settings.json`.
- **`_refresh_now_playing()` rebuilds both "now playing" cards from scratch every 700ms** — any new
  interactive control added to `_np_card` needs the same mid-drag-guard pattern
  (`self._np_video_dragging`/`self._np_audio_dragging`-style flag checked at the top of the refresh
  function) or a drag gesture will get destroyed mid-way.
- **Screenshot files saved via computer-use are not visible from the Bash tool in this environment** —
  don't assume they landed somewhere findable via `find`; ask the user where they actually saved them.
- **`design-review-brief.md` and `screenshot app/` are for a *separate* "Claude design"
  chat/tool, not this session** — don't try to do the visual redesign work here; this session's scope
  ends at preparing the brief + screenshots.
- Everything from previous handoffs still applies: **Windows parity is a hard requirement**; close
  Python before editing (`pkill` + verify with `ps aux`); macOS case-insensitive FS
  (`HANDOFF.md`/`handoff.md` collide); don't reintroduce `Toplevel` for editing popups (use
  `_open_modal`); `text_color="transparent"` crashes `CTkButton` (use `text=""`); don't use `place()`
  for hover overlays (use `grid()`/`grid_remove()`); don't compute wraplength without a "value changed"
  guard; `ProjectionWindow.close()`'s `on_close` re-entry guard; hymn/PPTX paths are stored *relative*
  to the app folder (always `os.path.abspath()` before handing to AppleScript/COM/native dialogs);
  `self._proj_mode` includes `"external"`; prefer `.configure()`/`.pack(after=)` over
  `pack_forget()`+`pack()` or widget recreation (visible white-flash risk with customtkinter's
  canvas-based rounded-rect rendering); `winfo_children()` order ≠ `pack_slaves()` order (use the
  latter for layout-order assertions); no automated test suite exists — headless scratch-settings
  `App()` instantiation + live computer-use screen access are the two verification methods that work.

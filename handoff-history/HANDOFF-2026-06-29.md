## 🎯 Goal

Desktop app (Mac + Windows) to run a full Seventh-day Adventist weekly service from one control panel.
The operator sits at the back of the hall, prepares the program the same morning, and during the
service projects hymns, Bible verses, presentations (PDF/PPTX), videos, a break countdown timer,
background music, a bell, and an offering QR — all onto a **second screen** (the user uses an iPad via
Sidecar as the projector).

"Done" = the operator never has to touch the projected screen; everything (incl. slide advance, video
transport, audio) is controlled from the app, and projection looks professional.

## ❌ Failed Attempts / Hard-won Knowledge

### Multi-channel seekable audio with pygame.mixer.Sound
- **What:** First audio engine used `pygame.mixer.Sound` on multiple Channels for hymn base + pause music.
- **Why it failed:** `Sound` cannot seek — dragging the seek bar restarted the track. **Fixed** by moving the main/controllable media to `pygame.mixer.music` (single seekable stream) and keeping pause-music on a Sound channel. Seeking uses `music.play(start=seconds)`.

### YouTube download "didn't work"
- **Root cause:** python.org Python on macOS has no CA certs → SSL CERTIFICATE_VERIFY_FAILED, AND GUI-launched app doesn't inherit shell PATH so the `yt-dlp` CLI wasn't found.
- **Fixed:** use the `yt_dlp` Python API (no PATH), set `os.environ["SSL_CERT_FILE"]=certifi.where()` at the top of `ui/app.py`, and pass bundled ffmpeg (`imageio_ffmpeg.get_ffmpeg_exe()`) via `ffmpeg_location`.

### Reading LND1991.bib
- It's a **Microsoft Access (Jet 3) MDB**. mdbtools/brew not available. Solved with pip `access-parser` (dev only) → converted to SQLite (`tools/convert_bib.py`). Runtime reads only SQLite.

### Tk `update()` busy-loop tests are flaky
- Headless smoke tests that drive the GUI with `update()` in a tight loop can starve worker threads / show false failures (esp. DB load + projection). The **mainloop-based** test (`smoke5.py`) is authoritative. Always reset `config/settings.json` `last_database` to `databases[0]` (the `ppt` folder with bases) before running smoke tests, or base-hymn assertions fail.

### DB load felt broken (~17s under load)
- Some PPTX (indices ~500–550 in `ppt/`) are very slow to parse with python-pptx; under system load total hit ~17s. **Fixed** with a folder cache keyed by filename→mtime in `config/db_cache/`. First parse ~2s, then instant.

### Hymn projection as our own text slides
- We project `slides_text` as white-on-dark autofit pages. **User rejects this** — wants the real PowerPoint visual. See Next Step #3.

## ⚠️ Gotchas / Traps

- **macOS case-insensitive FS**: `HANDOFF.md` and `handoff.md` are the same file.
- Don't reintroduce `Toplevel` for editing popups — use `_open_modal`.
- After running GUI smoke tests, **reset `config/settings.json`** (`last_database` → `databases[0]` = `ppt`, and reset `schedule`/history) — tests dirty it.
- customtkinter 6.0.0: some kwargs differ; `CTkButton` `hover` exists but prefer `hover_color`.
- `cursor="hand2"` ≠ the macOS system link cursor; use `pointinghand`.
- ffpyplayer prints harmless `swscaler ... No accelerated colorspace` warnings — ignore.
- Projection window is `overrideredirect(True)` on the secondary monitor — this likely breaks keyboard focus (relevant to remote/slide-advance bug #4).
- Smoke tests live in the scratchpad: `/private/tmp/claude-501/-Users-edoardo-Desktop-programma-inni/<session>/scratchpad/smoke*.py` (smoke through smoke9). They are NOT in the repo; recreate if needed. smoke5 is mainloop-based (authoritative).
